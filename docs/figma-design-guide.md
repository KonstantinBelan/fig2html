## 1. Как работает конвертер «под капотом» (простыми словами)

Вам не нужно быть программистом, чтобы понимать логику работы нашего алгоритма. Он действует как внимательный и опытный верстальщик:

```
    Входной файл .fig 
          │
          ▼
1. Чтение макета       ───►  Извлекает векторную геометрию, тексты, цвета и картинки
          │
          ▼
2. Понимание верстки   ───►  Переводит Auto Layout в гибкий Flexbox и CSS Grid
          │
          ▼
3. Связывание экранов  ───►  Понимает, где один и тот же блок на ПК и на смартфоне
          │
          ▼
4. Плавная резина      ───►  Рассчитывает формулы CSS clamp() для шрифтов и отступов
          │
          ▼
5. Генерация файлов    ───►  Чистый семантичный HTML5, стили style.css и легкие картинки
```

### Этапы работы движка:
1. **Чтение структуры**: Конвертер открывает нативный бинарный архив Figma (`.fig`) напрямую, считывая каждый слой, текстовый фрагмент, скругление, тень и изображение без промежуточных тяжелых плагинов и потери качества.
2. **Анализ Auto Layout**: Движок распознает, какие блоки выстроены горизонтально (в строку), какие вертикально (в колонку), где заданы промежутки (`Gap`) и внутренние поля (`Padding`). Они напрямую превращаются в современные правила CSS Flexbox.
3. **Умное слияние экранов**: Если на холсте нарисованы десктопная и мобильная версии одной страницы, движок не создаст два разных сайта. Он найдет одинаковые карточки, заголовки и логотипы, объединит их в **один HTML-элемент**, а различия плавно адаптирует.
4. **Математика плавной резины (Fluid Typography)**: Вам больше не нужно писать десятки медиа-запросов под каждый экран смартфона. Размер шрифта, например `48px` на ПК и `24px` на смартфоне, превратится в адаптивную формулу `clamp()`. Текст будет плавно масштабироваться под любую ширину окна пользователя.
5. **Токенизация**: Все цвета и отступы, оформленные через переменные Figma (Variables), превращаются в CSS-переменные (`:root { --primary-color: #3b82f6; }`).

## 2. Главные принципы создания идеального макета

Чтобы результат в браузере выглядел в точности как на вашем макете в Figma, придерживайтесь пяти «золотых» правил:

### ✅ 1. Используйте Auto Layout везде, где это возможно
* **Хорошо**: Фрейм карточки с Auto Layout (вертикальный стек), внутри заголовок, текст и кнопка. При изменении текста блок автоматически растягивается.
* **Плохо**: Набор разрозненных слоев, спозиционированных «на глаз» с абсолютными координатами.

### ✅ 2. Настоящие отступы вместо пустых прямоугольников
* **Хорошо**: В настройках Auto Layout задан `Gap: 16px` и `Padding: 24px`.
* **Плохо**: Прозрачные слои-распорки или пустые текстовые блоки, чтобы отодвинуть один элемент от другого.

### ✅ 3. Векторные иконки — во фреймах фиксированного размера
* Каждая иконка (стрелка, лупа, иконка корзины) должна быть заключена во фрейм с понятным размером, например `24×24px` или `32×32px`. Это гарантирует, что в HTML кнопка или поле поиска не деформируются.

### ✅ 4. Не используйте скрытые «мусорные» слои
* Выключенные слои с нулевой прозрачностью (`opacity: 0`) или отключенным глазиком без надобности лучше удалять перед финальным экспортом. Если слой нужен для адаптива (например, мобильное меню), дайте ему правильное имя.

## 3. Управление размерами: Fill, Hug и Fixed

В Figma в панели Auto Layout есть три ключевых режима изменения размеров: **Fixed**, **Hug contents** и **Fill container**. Это главные строительные блоки верстки!

| Режим в Figma | Поведение в дизайне | Как превращается в CSS | Для чего использовать |
| :--- | :--- | :--- | :--- |
| **Hug contents** *(По контенту)* | Сжимается до размеров своего содержимого | `width: fit-content` / `align-self: flex-start` | **Кнопки, бейджи, теги, аватары, чипы фильтров**. Элемент никогда не растянется на весь экран! |
| **Fill container** *(Заполнить)* | Растягивается на всю ширину родителя | `width: 100%` / `flex: 1` / `align-self: stretch` | **Заголовки, текстовые абзацы, карточки в сетке, контейнеры секций**. |
| **Fixed** *(Фиксированный)* | Жестко заданные пиксели (например, 320px) | `width: 320px; flex-shrink: 0` | **Сайдбары фиксированной ширины, иконки, иллюстрации**. |

> [!TIP]
> **Почему бейджи и кнопки не должны растягиваться на весь экран?**
> Если для бейджа задан режим **Hug contents**, наш движок автоматически пропишет `align-self: flex-start` на десктопе и `align-self: center` на мобильном. Бейдж останется аккуратной пилюлей и не растянется на всю ширину строки!

### 📏 Ограничения размеров: Min / Max Width и Height
Начиная с версии **v1.5.2**, конвертер полностью поддерживает нативные ограничения размеров Figma:
* **Min W** и **Max W** (минимальная и максимальная ширина)
* **Min H** и **Max H** (минимальная и максимальная высота)

**Где это незаменимо:**
* **Ограничение контентной области**: задайте для контейнера `Fill container` и добавьте `Max W: 1200px` — блок будет гибко сжиматься на мобильных экранах, но никогда не разъедется шире 1200px на UltraWide мониторах.
* **Фиксация высоты карточек**: для карточек с разным объемом контента задайте `Min H: 380px` — карточки в одном ряду будут аккуратно выровнены по высоте, но при необходимости вместят длинный текст без выпадения элементов.

## 4. Одностраничные сайты (Single Page / Landing Page)

При создании лендинга или промо-страницы организуйте макет следующей структурой:

1. **Главный фрейм страницы**:
   - Назовите фрейм `Home`, `Landing` или `Page`.
   - Рекомендуемая ширина для десктопа: `1440px` (или `1200px` / `1920px`).
   - Настройте Auto Layout: **Vertical**, выравнивание по центру, отступы по бокам при необходимости.
2. **Секции страницы**:
   - Внутри главного фрейма разместите независимые блоки-секции:
     - `header` — шапка сайта с навигацией
     - `hero` — главный первый экран с оффером
     - `features` — преимущества или карточки услуг
     - `pricing` — тарифы
     - `faq` — вопросы и ответы
     - `footer` — подвал сайта
   - Для всех секций включите **Fill container** по ширине. Контент внутри секций центрируйте контейнером (например, `container` шириной `1200px` с центровкой).

## 5. Многостраничные сайты (Multi-Page Websites)

Наш компилятор умеет автоматически генерировать целые многостраничные порталы со связанными ссылками и общей таблицей стилей!

### 🏷️ Теги в названиях страниц
Чтобы движок понял, какие фреймы являются отдельными веб-страницами, добавьте специальный тег в имя фрейма:

| Тег в названии фрейма | Сгенерированный файл | Назначение |
| :--- | :--- | :--- |
| `[page] Главная` или `[page:index] Home` | `index.html` | Главная страница сайта |
| `[page] О компании` или `[page:about] About` | `about.html` | Страница «О компании» |
| `[page] Услуги` или `[page:services] Services` | `services.html` | Каталог услуг |
| `[page] Контакты` или `[page:contacts] Contacts` | `contacts.html` | Страница контактов |

> Поддерживаются различные форматы тегов: `[page]`, `[страница]`, `[p]`, `#page`, `/page`.

### 🚫 Теги исключения (черновики и UI-киты)
Часто на холсте лежат палитры цветов, компоненты или черновики, которые **не должны** попадать в готовый сайт. Добавьте к ним тег исключения:

* `[exclude] Палитра цветов`
* `[ignore] Черновик новой шапки`
* `[исключить] UI Kit Компоненты`

Движок пропустит эти фреймы при сборке HTML, сохранив чистоту проекта.

## 6. Адаптивный дизайн: Desktop, Tablet и Mobile

Самая мощная возможность версии **v1.4.0** — создание адаптивного сайта из нескольких артбордов Figma.

### 📱 Как именовать адаптивные фреймы
Создайте для одного экрана 2–3 фрейма под разные разрешения и добавьте понятный суффикс:

```
├── Page [desktop]      (например, ширина 1440px)
├── Page [tablet]       (например, ширина 768px)
└── Page [mobile]       (например, ширина 440px или 375px)
```

Также поддерживаются форматы:
* Через собачку: `Catalog @1440`, `Catalog @768`, `Catalog @440`
* С точной шириной: `Home [w:1440]`, `Home [w:440]`
* Через разделитель: `Landing / Desktop`, `Landing / Mobile`

### 🎯 Золотое правило брейкпоинтов
**Ширина артборда в Figma — это реальная ширина брейкпоинта в CSS!**
* Если вы нарисовали мобильный фрейм шириной **`440px`**, в коде появится точный медиа-запрос `@media (max-width: 440px)`.
* Если вы нарисовали планшет шириной **`768px`**, адаптив сработает при `768px`.
* Никаких принудительных или скрытых чисел — верстка сработает ровно там, где вы ее спроектировали!

### 🔄 Одинаковые имена для связанных элементов
Чтобы карточка или заголовок плавно уменьшались в размерах от десктопа к мобильному:
* Называйте элемент одинаково на обоих артбордах!
* Пример: блок карточки на десктопе назовите `card`, и на мобильном тоже назовите `card`.
* Внутри карточки заголовок `card-title` на десктопе и `card-title` на мобильном.
* Движок поймет, что это один и тот же объект, и сам вычислит формулу плавного изменения шрифта:
  ```css
  font-size: clamp(1.125rem, 0.95rem + 0.6vw, 1.5rem);
  ```

### 🍔 Специфичные элементы (Десктопное меню vs Бургер)
* Если на десктопе есть горизонтальное меню `nav-links`, а на мобильном кнопка `burger-btn`:
* Просто оставьте `nav-links` только на десктопном фрейме, а `burger-btn` только на мобильном.
* Движок автоматически скроет меню на телефонах (`display: none`) и покажет кнопку бургера (`display: flex`), без дополнительных настроек!

## 7. Семантические теги и именование слоев

Наш движок анализирует имена слоев и автоматически генерирует правильные теги HTML5:

| Имя слоя в Figma | Сгенерированный HTML тег | Пример в коде |
| :--- | :--- | :--- |
| `btn`, `button`, `btn-primary`, `btn-submit` | `<button>` | `<button class="btn-primary">Купить</button>` |
| `title`, `h1`, `heading` | `<h1>` (или `<h2>`, `<h3>` по иерархии) | `<h1 class="title">Заголовок</h1>` |
| `subtitle`, `desc`, `p`, `paragraph` | `<p>` | `<p class="subtitle">Описание продукта</p>` |
| `link`, `a`, `href` | `<a>` | `<a href="#" class="link">Подробнее</a>` |
| `header` | `<header>` | `<header class="header">...</header>` |
| `nav`, `menu`, `navigation` | `<nav>` | `<nav class="nav">...</nav>` |
| `footer` | `<footer>` | `<footer class="footer">...</footer>` |
| `Input[text]`, `Input[email]` | `<input type="...">` | `<input type="email" placeholder="...">` |
| `badge`, `tag`, `chip` | `<span class="badge">` | `<span class="badge">New</span>` |

### 📋 Нативные списки и нумерация (Lists & Spacing)
Вместо того чтобы вручную рисовать маркеры точек или цифры отдельными текстовыми слоями:
* Выделите текст и в панели типографики Figma выберите **List style**:
  - `Numbered` (1, 2, 3...) — движок создаст семантичный нумерованный список `<ol>` с тегами `<li>` и стилем `list-style-type: decimal`.
  - `Bulleted` (•) — создаст маркированный список `<ul>` с тегами `<li>`.
* Используйте параметр **List spacing** в свойствах текста, чтобы настроить расстояние между пунктами списка — движок транслирует его в правильный отступ между элементами в CSS.

> [!NOTE]
> Если слою не присвоено специальное имя (например, стандартное `Frame 42`), движок создаст семантичный `<div>` или `<section>` с аккуратным и чистым CSS-классом.

## 8. Переменные Figma (Variables & Design Tokens)

Использование **Figma Variables** — это профессиональный стандарт современной дизайн-системы. Конвертер умеет читать и экспортировать их напрямую:

### 1. Цвета (Color Tokens)
* Создайте переменную цвета в панели Local Variables, например:
  - `primary-color` = `#2563eb`
  - `background-dark` = `#0f172a`
  - `text-muted` = `#94a3b8`
* Привяжите переменную к заливке или обводке слоев.
* В готовом CSS появится чистый блок токенов:
  ```css
  :root {
    --primary-color: #2563eb;
    --background-dark: #0f172a;
    --text-muted: #94a3b8;
  }
  ```

### 2. Скругления углов (Radius) и Отступы (Spacing)
* Числовые переменные для радиуса (`radius-sm = 6`, `radius-lg = 16`) и отступов (`gap-md = 16`) автоматически транслируются в токены верстки.

## 9. Шрифты, иконки и графика

### 🔤 Шрифты и кадрирование (Vertical Trim)
* Движок полностью поддерживает Google Fonts и системные шрифты.
* Если вы используете шрифты вроде *Inter*, *Roboto*, *Fira Code*, *Playfair Display*, в сгенерированный HTML будет автоматически добавлена ссылка на подключение веб-шрифтов:
  ```html
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700&display=swap" rel="stylesheet">
  ```
* **Вертикальное кадрирование (Vertical Trim)**: для крупных акцентных чисел, таймеров и заголовков используйте настройку *Vertical trim: Cap height to baseline* в дополнительных параметрах текста Figma. Это убирает лишние невидимые поля шрифта сверху и снизу, а движок компилирует это в точные правила CSS `text-box-trim: trim-both; text-box-edge: cap alphabetic`.

### 🖼️ Изображения и Retina 2x
* Картинки в макете экспортируются в высоком разрешении с коэффициентом 2x для экранов Retina.
* При включенных флагах оптимизации (`--webp` или `--avif`) изображения сжимаются в современные легкие форматы, экономя до 70% веса страницы.

### 📐 Векторная графика, иконки и вырезы (`EvenOdd`)
* Иконки и векторные иллюстрации переводятся в чистый и компактный векторный код SVG.
* **Составные иконки с вырезами (EvenOdd)**: если иконка содержит отверстия (замочная скважина в щите, прорези в корзине, отверстия в бейдже), упакуйте векторные слои во фрейм размером до 200×200px или объедините через `Boolean Union`/`Flatten`. Движок сохраняет алгоритм `fill-rule="evenodd"`, гарантируя прозрачные отверстия в векторе без закрашивания.
* **Параметрические фигуры (Star & Polygon)**: используйте нативные фигуры Figma `Star` (звезды с любым количеством лучей) и `Polygon` со скруглением `Corner radius`. Движок v1.5.2 синтезирует плавные дуги SVG (`Q`/`A`), сохраняя фигуру в легком векторном коде.
* **Режимы наложения (Blend Modes)**: при использовании эффектов наложения (`Multiply`, `Soft Light`, `Overlay`) для фоновых декоративных подложек отключайте свойство `Clip content` у родительского фрейма, чтобы подложка гармонично смешивалась со смежными блоками секции.

## 10. Чек-лист перед экспортом: 10 шагов к успеху

Перед запуском компиляции проверьте свой макет по этому простому списку:

- [ ] **1. Все блоки собраны на Auto Layout**: элементы не раскиданы хаотично по абсолютным координатам.
- [ ] **2. Правильные настройки ресайза и лимитов**: кнопки и бейджи имеют статус `Hug contents`, текстовые блоки и карточки — `Fill container`, а широкие контейнеры ограничены через `Max W`.
- [ ] **3. Названия фреймов проверены**:
  - Для одной страницы: `Page [desktop]` (1440px) и `Page [mobile]` (440px).
  - Для многостраничника: `[page] Home`, `[page] About`, `[page] Contacts`.
- [ ] **4. Лишнее исключено**: черновики и палитры помечены тегом `[exclude]`.
- [ ] **5. Схожие элементы названы одинаково**: карточки на десктопе и смартфоне имеют одинаковое имя `card`.
- [ ] **6. Иконки упакованы во фреймы**: каждая векторная иконка лежит во фрейме с четкими размерами (например, 24×24 или до 200×200), а вырезы используют `EvenOdd`.

## 🚀 Команды для запуска

Скомпилировать макет в чистый сайт:

```bash
# 1. Автоматический запуск декомпилятора в отдельную папку:

# 2. С оптимизацией картинок в WebP:
node cli-reverse.js my-design.fig dist/index.html -s --webp

node cli-reverse.js my-design.fig dist/index.html -s --responsive
```
