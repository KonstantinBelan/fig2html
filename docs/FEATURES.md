# ⚡ Возможности и архитектура Figmatik

**Figmatik** — это высокопроизводительный движок двусторонней трансляции между нативными бинарными файлами Figma (`.fig`) и современным веб-стеком (чистый семантический HTML5/CSS, Tailwind CSS v3/v4, React, Vue, Svelte).

Движок работает автономно на уровне бинарной спецификации **Kiwi Schema v101** и алгоритмов сжатия **Zstandard**, не требуя наличия запущенного браузера, headless Chrome, Figma Desktop или плагинов.

## 1. Ключевые архитектурные преимущества

- **100% нативный формат Figma (`.fig`)**:
  - Файлы открываются непосредственно в Figma Desktop и Figma Web без установки плагинов.
  - Структура архива соответствует официальному бинарному формату: заголовок `fig-kiwi`, сжатие `zstd` и потоки данных `canvas.kiwi`.
- **Pure ECMAScript Modules (ESM)**:
  - Кодовая база написана на нативном современном JavaScript (`node:*`, `"type": "module"`).
  - Прямой запуск в Node.js 18, 20, 22 без этапа транспиляции или бандлинга (No Build Step).
- **Строгая типизация TypeScript**:
  - Официальный файл определений `index.d.ts` с описанием всех структур, опций и Kiwi AST узлов.
  - Полная поддержка режимов TypeScript `NodeNext` и `Bundler`.
- **Zero-Dependency Runtime (CLI)**:
  - Для работы компилятора и декомпилятора не требуются внешние облачные сервисы, авторизация или активная подписка Figma.

## 2. Декомпилятор: .fig ➔ HTML/CSS

### 2.1. Layout Synthesis Engine (Синтез верстки без Auto Layout)

Если дизайнер создал макет без использования Auto Layout (слои расположены абсолютными координатами на холсте), большинство конвертеров превращают верстку в полотно из сотен `position: absolute`.

Figmatik решает эту проблему с помощью **5-фазного эвристического движка Layout Synthesis Engine**:

1. **Фаза 1: Spatial Normalization & Indexing**:
   - Построение точных двумерных ограничивающих рамок (`BoundingBox`) для каждого узла.
   - Пространственное индексирование слоев и расчет топологического порядка наложения (`z-index`).
2. **Фаза 2: Background & Container Induction**:
   - Автоматическое обнаружение графических прямоугольников-подложек (`RECTANGLE` с заливкой, обводкой, скруглениями или тенями).
   - Повышение подложек до роли семантических контейнеров (`<div>`, `<section>`, `<header>`, `<button>`) с переносом визуальных свойств на контейнер.
3. **Фаза 3: Recursive XY-Cut & Fuzzy Clustering**:
   - Проекция элементов на горизонтальную и вертикальную оси (1D-гистограммы).
   - Нечеткая кластеризация интервалов с допуском неточностей дизайнера $\epsilon = 3\text{px}$ (Fuzzy Tolerance Clustering) для автоматического выравнивания строк, колонок и карточек (`align-items: center`, `justify-content: space-between`).
4. **Фаза 4: Grid & Matrix Induction**:
   - Обнаружение регулярных $N \times M$ матриц одинаковых карточек с равномерным шагом.
   - Синтез адаптивной сетки `display: grid; grid-template-columns: repeat(N, 1fr); column-gap: ...; row-gap: ...;`.
5. **Фаза 5: Flexbox Property Synthesis**:
   - Вычисление внутренних отступов (`padding`), зазоров (`gap`), растяжения (`align-self: stretch`, `width: 100%`).
   - Изоляция декоративных оверлеев (бейджи, иконки закрытия) с сохранением точечного `position: absolute`.

> Флаг управления: `--smart-layout` (включен по умолчанию). Для намеренного отката к абсолютным координатам доступен флаг `--no-smart-layout`.

### 2.2. Adaptive Multi-Breakpoint Engine (Объединение экранов)

Большинство дизайнеров рисуют разные экраны сайта как отдельные артборды: Desktop (1440px), Tablet (768px), Mobile (375px).

Figmatik объединяет связанные фреймы в **единый канонический HTML-документ**:

- **AST Similarity Matching**: алгоритмическое сопоставление элементов между экранами по именам слоев, типам нод, текстовому содержимому и иерархическому положению в дереве.
- **Плавная интерполяция через `clamp()`**:
  - Числовые свойства (`font-size`, `padding`, `gap`, `border-radius`, `width`) преобразуются в адаптивную функцию:
    $$\text{clamp}(V_{\min},\; S \cdot 100\text{vw} + I,\; V_{\max})$$
  - Размеры плавно изменяются при ресайзе окна браузера без рывков.
- **Медиа-запросы для структурных различий**:
  - Изменения структуры (`flex-direction: row` ➔ `column`, количество колонок сетки) аккуратно выносятся в `@media (max-width: 768px)`.
- **Поддержка подходов**:
  - Desktop-first (по умолчанию, запросы `max-width`).
  - Mobile-first (флаг `--mobile-first`, запросы `min-width`).
- **Управление эксклюзивными элементами (Exclusive Elements)**:
  - Десктопное меню (`.nav-links`) и мобильный бургер (`.burger-btn`) сосуществуют в одном дереве и переключаются через чистые CSS-правила видимости (`display: none` / `display: flex`) без дублирования верстки и без JavaScript.

### 2.3. Graphic Subtree Collapsing & Cumulative Baking (Запекание графики)

При экспорте сложных иллюстраций дизайнеры часто создают цепочки из 5–7 уровней вырожденных групп (`Group -> Group -> Mask Group -> Group -> Image`). При обычной конвертации это приводит к раздутому DOM и каскадным сбоям CSS.

Figmatik использует алгоритм **Graphic Subtree Collapsing**:

- **Детекция вырожденных графических цепочек**:
  - Автоматическое распознавание поддеревьев, содержащих только растровые изображения, обрезки и маски, без текстовых или интерактивных элементов.
- **Кумулятивное матричное умножение**:
  - Перемножение 2D аффинных трансформаций по всей цепочке вложенности:
    $$M_{\text{cumulative}} = M_1 \times M_2 \times \dots \times M_n$$
  - Извлечение суммарного угла поворота $\theta = \text{atan2}(b, a)$, масштаба и трансляции.
- **Аппаратное запекание через Sharp**:
  - Поворот, кадрирование по маске и масштабирование Retina @2x с честным альфа-каналом.
- **Схлопывание DOM**:
  - 5+ уровней вложенности заменяются на **один чистый семантический тег `<img>`** с точными CSS-габаритами.
- **Multiply-to-Alpha Baking**:
  - Для логотипов и изображений с `blendMode: MULTIPLY` на белом фоне движок автоматически вычисляет альфа-прозрачность ($\alpha = 255 - \min(R,G,B)$), устраняя белые фоновые плашки при переносе в браузер.

### 2.4. Smart Anchors & Constraint Resolution

Для абсолютно позиционированных элементов движок интеллектуально выбирает сторону привязки:
- **Учет Figma Constraints**: при `horizontalConstraint === 'MAX'` генерируется `right`, при `verticalConstraint === 'MAX'` — `bottom`.
- **Геометрическая близость**: если элемент расположен ближе к правой или нижней грани контейнера, автоматически генерируются `right` / `bottom` вместо жестких `top` / `left`.
- **Сохранение высоты в Bento-сетках**: защита `Fixed height` у карточек в вертикальных синтезированных колонках Bento-сеток от нежелательного растяжения во `flex: 1`.
- **4-сторонние асимметричные отступы**: полное восстановление опущенных нулевых отступов из Kiwi, исключающее схлопывание стилей в симметричный `padding`.
- **Stacking Order Resolution**: автоматическое выявление элементов, выступающих за пределы родительского фрейма (bleeding absolute children), с изолированием стекового контекста через `position: relative; z-index: 1`.

### 2.5. Многостраничный импорт (Multi-Page Engine)

Экспорт целых сайтов за один вызов команды:

- **Трёхуровневая система детекции страниц**:
  1. *Явные теги*: фреймы с префиксом `[page]`, `[страница]`, `#page`. Имя очищается и транслитерируется (`[page] About Us` ➔ `about-us.html`).
  2. *Экранные артборды с Outlier Detection*: автоматическое определение артбордов экрана (ширина $\ge 320\text{px}$, высота $\ge 400\text{px}$). Кластеризация по медианному размеру отсекает всплывающие окна и мелкие модалки.
  3. *Canvas вкладки*: декомпиляция страниц документа Figma (`--all-canvases`).
- **Теги исключения (`[exclude]`, `[исключить]`)**: возможность исключать черновики и служебные артборды прямо в Figma.
- **Smart DRY CSS**: повторяющиеся компоненты на разных страницах получают общий класс в едином файле `css/style.css`, а уникальные свойства изолируются страничными модификаторами (`.btn--cart`).
- **Единый пул ассетов**: дедупликация изображений по SHA-1 хешу в общей папке `img/`.

---

### 2.6. Типографика, Google Fonts и кадрирование

- **Google Fonts Auto-Detection**: автоматическое формирование тегов `<link rel="stylesheet">` для предзагрузки найденных в макете шрифтов.
- **Встроенная таблица метрик шрифтов (`FONT_METRICS_TABLE`)**: точный расчет физических габаритов текстовых блоков (Inter, Roboto, Montserrat, Poppins, Fira Code и др.).
- **Кадрирование зазоров шрифтов (`leadingTrim`)**: генерация современных CSS-свойств `text-box-trim: trim-both` и `text-box-edge: cap alphabetic` для идеальной вертикальной посадки заголовков без лишних отступов шрифта.
- **Градиентный текст**: поддержка линейных и радиальных градиентов для текстовых слоев с генерацией `-webkit-background-clip: text` и `-webkit-text-fill-color: transparent`.
- **Truncate text**: трансляция обрезки текста из Figma в `text-overflow: ellipsis; white-space: nowrap; overflow: hidden`.
- **Семантические списки `<ol>` и `<ul>`**: сохранение нумерации, маркеров и интервалов `listSpacing`.

---

### 2.7. Цвета, градиенты и визуальные эффекты

- **Цветовые модели**: полная поддержка HEX (3, 4, 6, 8 символов), RGB, RGBA, HSL, HSLA, современного пробельно-слэшевого синтаксиса `rgb(255 0 0 / 50%)` и динамического цвета `currentColor`.
- **Градиенты**: точный расчет 2x3 аффинной матрицы для любых углов поворота (`deg`, `rad`, `turn`) и направлений (`to right`, `to bottom-right`).
- **Тени и размытия**: множественные `box-shadow`, внутренние тени `inset`, фоновые размытия `backdrop-filter: blur(...)` и размытия слоя `filter: blur(...)`.
- **Режимы наложения**: чистый экспорт `mix-blend-mode` без паразитного засорения слоев нормальным режимом, поддержка `LUMINOSITY` в связке с `filter: grayscale(1)`.

### 2.8. Режимы верстки: Fluid, Relative и Default

- **Fluid (`--fluid`)**:
  - Контейнер растягивается на всю ширину экрана: `width: 100vw; min-height: 100dvh`.
  - Типографика и отступы рассчитываются через адаптивные формулы `clamp()`.
  - Использование единиц `rem`, `vw`, `vh`.
- **Relative (`--relative`, `--rem`)**:
  - Замена всех абсолютных пикселей `px` на относительные единицы `rem`, `em`, `vw`, `vh` для гармоничного масштабирования интерфейса.
- **Default**:
  - Классическая фиксированная верстка с точным соответствием макету в `px`.

---

### 2.9. Дизайн-токены и Figma Variables

- **Двусторонняя трансляция**:
  - Экспорт переменных Figma в CSS-переменные `:root` с поддержкой переключения тем (`[data-theme="Dark"]`).
  - Экспорт нативных Figma Variables в стандартный JSON-файл спецификации W3C Design Tokens (`--tokens tokens.json`).
- **Шкала примитивных токенов отступов (`--spacing-tokens`)**:
  - Автоматическое выявление повторяющихся шагов отступов и создание шкалы `:root { --space-1: 4px; --space-2: 8px; ... }`.
- **Изоляция коллизий токенов**:
  - Разделение токенов скруглений (`--radius-16px`) и отступов (`--space-4: 16px`) в независимые переменные.

---

### 2.10. Стандарты доступности (A11y) и i18n

- **Доступность из коробки**:
  - Декоративная графика автоматически получает `alt=""` и `aria-hidden="true"`.
  - Векторные SVG-иконки помечаются `aria-hidden="true" focusable="false"`.
  - Кнопки-иконки без текстового наполнения снабжаются вычисляемым атрибутом `aria-label` (например, `aria-label="Close"`, `aria-label="Search"`).
  - Навигационные блоки получают тег `<nav aria-label="...">`.
  - В глобальный CSS Reset встроен доступный фокус с клавиатуры: `:focus-visible { outline: 2px solid currentColor; outline-offset: 2px; }`.
- **Автоматическая локализация (i18n)**:
  - Анализ соотношения кириллицы и латиницы в тексте макета с автоматической генерацией `<html lang="en">` или `<html lang="ru">` и локализованных A11y-подписей.
  - Флаг явного переопределения: `--lang <code>`.

---

### 2.11. Оптимизация и обработка изображений

- **Retina 2x качество**: автоматическое масштабирование картинок под физические размеры отображения в CSS с множителем x2.
- **Адаптивный `srcset`**: генерация наборов картинок под разные плотности экранов и вьюпорты смартфонов, планшетов и десктопов (отключается флагом `--no-srcset`).
- **Современные форматы**: конвертация на лету в `WebP` (`--webp`) и `AVIF` (`--avif`).
- **Lossless сжатие**: оптимизация размера файлов без потери визуального качества (`--compress`).

## 3. Enterprise Tailwind CSS (v3 & v4 Oxide)

Figmatik предоставляет полноценную enterprise-поддержку **Tailwind CSS** для декомпиляции и обратной компиляции.

### 3.1. Поддержка спецификаций Tailwind v4 и v3

- **Tailwind v4 (Oxide / CSS-first)**:
  - Генерация директивы `@import "tailwindcss";`.
  - Экспорт цветов и шрифтов в современную секцию `@theme` с CSS-переменными темы.
- **Tailwind v3**:
  - Формирование классических файлов `tailwind.config.js` и `postcss.config.js`.

---

### 3.2. Интеллектуальная привязка к 4px сетке (Scale Snapping)

- Значения размеров и отступов автоматически сопоставляются со стандартной шкалой Tailwind (`p-4`, `m-6`, `gap-8`, `rounded-xl`, `max-w-md`).
- При отклонении от сетки свыше порога толерантности (`--tailwind-tolerance`) генерируются валидные JIT-утилиты произвольных значений: `p-[18px]`, `w-[327px]`.

---

### 3.3. Экспорт в компонентные фреймворки (React, Vue, Svelte)

- **React TSX (`--react`)**:
  - Создание функционального React-компонента на TypeScript.
  - Атрибуты классов преобразуются в `className`, встроенные SVG-атрибуты трансформируются в camelCase (`fillRule`, `clipRule`, `strokeWidth`), теги делаются самозакрывающимися.
- **Vue 3 SFC (`--vue`)**:
  - Создание Single File Component с секциями `<template>`, `<script setup lang="ts">` и `<style scoped>`.
- **Svelte (`--svelte`)**:
  - Генерация чистого компонента Svelte `.svelte`.

---

### 3.4. Скаффолдинг готовых production-проектов

Флаг `--scaffold <dir>` развертывает полностью настроенный production-репозиторий:
- Файл `package.json` с настроенными зависимостями и скриптами `dev`, `build`, `preview`.
- Конфигурация сборщика (Vite / Tailwind CLI / PostCSS).
- Главный файл стилей, HTML-шаблон и сгенерированные компоненты.

---

### 3.5. Гибридный режим BEM + @apply

Режим `--tailwind-mode hybrid`:
- Разметка сохраняет семантические имена классов по BEM (`.hero-section`, `.hero-title`, `.btn-primary`).
- Стили выносятся в отдельный CSS-файл с директивами `@apply`:
  ```css
  .btn-primary {
  ```

## 4. Компилятор: HTML/CSS ➔ .fig

### 4.1. Полная конвертация документа и холста

- Конвертация начинается непосредственно от корневого узла `<body>`.
- Сохраняются реальные размеры документа (например, вертикальные посты/слайды 1080×1350 или широкие десктопные лэндинги) и фон страницы.
- Автоматическое вычисление физических координат дочерних элементов через пред-рассчитанный Layout Pass.

---

### 4.2. Auto Layout v4 и пре-компьютированный Layout Pass

- Полное соответствие спецификации Figma Auto Layout v4:
  - Направления: `display: flex` / `inline-flex` (`flex-direction: row | column`).
  - Режимы сайзинга: **Hug contents** (`RESIZE_TO_FIT`), **Fixed** (`FIXED`), **Fill container** (`STRETCH`) по обеим осям (`stackPrimarySizing`, `stackCounterSizing`).
  - Выравнивания: `justify-content` (`flex-start`, `center`, `flex-end`, `space-between`, `space-evenly`).
  - Выравнивание по поперечной оси: `align-items` (`flex-start`, `center`, `flex-end`, `baseline`, `stretch`).
  - Отступы: `gap`, независимые отступы с 4 сторон (`padding: top right bottom left`).
- **Эмуляция внешних отступов (margin) для текста**: автоматическое оборачивание текста с `margin` во вспомогательные Auto Layout контейнеры.

---

### 4.3. CSS Grid в Auto Layout Wrap

- Парсинг сеток `display: grid` и свойств `grid-template-columns` (`repeat(N, 1fr)`, `repeat(N, 200px)`).
- Интеллектуальная трансляция сетки в Auto Layout v4 с `stackWrap: WRAP` и точным расчетом ширин колонок.

---

### 4.4. Экспорт CSS-переменных в нативные Figma Variables

- CSS-переменные из блока `:root` конвертируются в нативные бинарные коллекции Figma: узлы `VARIABLE_SET` и `VARIABLE` типов `COLOR`, `FLOAT`, `STRING`.
- Элементы макета связываются с переменными через `parameterConsumptionMap`.

---

### 4.5. Интерактивные состояния :hover и прототипирование

- Автоматическое распознавание CSS-псевдоклассов `:hover`, `:active`, `:focus`.
- Генерация нативных взаимодействий Figma: `prototypeInteractions` с триггером `WHILE_HOVERING` и переходом `SWAP_STATE`.

---

### 4.6. Векторные пути, SVG-спрайты и иконки

- Парсинг векторных элементов `<svg>`, `<path>`, `<circle>`, `<rect>`, `<polygon>`.
- Поддержка SVG-спрайтов `<use href="#id">` с сохранением свойств обводки (`stroke`, `stroke-width`, `currentColor`) и заливки.
- Компиляция SVG-путей в бинарные потоки `commandsBlob` и `VectorNetwork` узлов `VECTOR`.

---

### 4.7. Двусторонняя компиляция Tailwind в Figma

- Компилятор распознает утилиты Tailwind (`flex`, `items-center`, `justify-between`, `gap-4`, `p-6`, `bg-indigo-600`, `rounded-2xl`, `shadow-lg`, `text-xl`, `font-bold`).
- Утилиты мгновенно вычисляются и компилируются в нативные параметры Auto Layout фреймов, заливок и скруглений Figma без потери семантики.
